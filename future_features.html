الميزات المستقبلية

خطة الميزات التي تجعل النظام منتجاً قابلاً للبيع، مستوحاة من Notion وMonday وClickUp وLinear.

خارج هذا الملف: كل ما هو مذكور في BITRIX24_IMPLEMENTATION_STEPS.md سيُبنى هناك على الطرفين، ولا يتكرر هنا: المشاركون والمراقبون، المهام الفرعية، Checklists، تتبع الوقت والمؤقت، الملفات، نتائج المهمة، شات المهمة، سجل التغييرات، جدولا الحالة والأولوية القابلان للتعديل، وتسجيل الدخول عبر Bitrix (OAuth).

ما هو موجود حالياً

Kanban، Calendar، Saved Views، Export، تعديل مباشر (inline)، تعليقات، Activity Log، أدوار وصلاحيات.

0. قرار معماري قبل أي ميزة: Multi-tenancy

النظام حالياً يخدم شركة واحدة. لبيعه كـ SaaS يجب أن يكون لكل شركة Workspace منفصل ببياناتها ومستخدميها وخطة اشتراكها.

  • جدول workspaces وعمود workspace_id على كل الجداول الأساسية، مع Global Scope في Laravel يفلتر تلقائياً.
  • مستخدم واحد يمكن أن ينتمي لأكثر من Workspace (مع تبديل سريع بينها).
  • ربط Bitrix يصبح على مستوى الـ Workspace (كل شركة ببوابتها).

لماذا أولاً؟ يمس كل الجداول، وكل تأجيل يجعله أصعب.

1. أساسيات ناقصة

الميزة التفاصيل
Labels / Tags ملونة، على مستوى المشروع أو الـ Workspace، مع فلترة وتجميع
@Mentions في الوصف والتعليقات، مع اقتراح تلقائي للأعضاء
مركز الإشعارات داخل التطبيق (جرس + غير مقروء)، إيميل، ولاحقاً Push. مع تفضيلات لكل مستخدم
Custom Fields أهم ميزة في Monday: كل مشروع يضيف حقوله (رقم، تاريخ، dropdown، شخص، رابط، checkbox، عملة)
أعمدة Kanban لكل مشروع فوق جدول الحالات العام: كل مشروع يختار ويرتّب الحالات التي يستخدمها
مهام متكررة (Recurring) يومي / أسبوعي / شهري / مخصص، عبر Scheduler في Laravel
Dependencies "هذه المهمة لا تبدأ قبل انتهاء تلك" (blocks / blocked by)، مع تحذير عند تغيير التواريخ

2. طرق العرض (Views)

الموجود: Board وCalendar. المطلوب:

  • Table / List: مثل Excel، تعديل الخلية مكانها، Group By، أعمدة الـ Custom Fields، تغيير عرض وترتيب الأعمدة.
  • Timeline / Gantt: يعرض الـ Dependencies، سحب لتغيير التواريخ والمدة.
  • Workload: من محمّل زيادة ومن متاح، حسب عدد المهام أو الساعات المقدرة.
  • Dashboard بـ Widgets: كل مستخدم يركّب لوحته (charts، أرقام، مهام متأخرة، تقدم المشاريع).
  • تقارير: Burndown، Cycle time، المهام المتأخرة، إنتاجية الفريق.

3. الأتمتة (Automations)

الميزة التي تبيع Monday. منشئ قواعد بدون كود:

عندما تصبح الحالة "In Review" ← عيّن المدير + أرسل إشعاراً عندما يتجاوز الموعد النهائي ← غيّر الأولوية إلى Urgent + أرسل إيميلاً عندما تُنشأ مهمة في مشروع X ← أضف Label "جديد"

  • Triggers: إنشاء مهمة، تغيير حالة/أولوية/مسؤول، اقتراب أو تجاوز الموعد، إضافة تعليق.
  • Conditions: المشروع، الأولوية، Label، قيمة Custom Field.
  • Actions: تغيير حقل، تعيين شخص، إشعار، إيميل، WhatsApp، Webhook، إنشاء مهمة.
  • التنفيذ: Laravel Events + Queues + جدول automation_rules + سجل تنفيذ لكل قاعدة.
  • قوالب جاهزة للقواعد الشائعة.

4. أفكار من Notion

  • Docs / Wiki لكل مشروع: محرر Blocks (TipTap أو BlockNote)، مع تضمين وربط المهام داخل الصفحة.
  • Rich text في وصف المهمة والتعليقات.
  • Templates: قوالب مشاريع ومهام جاهزة (إطلاق منتج، Onboarding موظف، Sprint) تُنسخ بضغطة، مع إمكانية حفظ مشروع كقالب.

5. سرعة الاستخدام (مثل Linear)

  • Command Palette (Ctrl+K): بحث شامل في المهام والمشاريع والأشخاص وتنفيذ الأوامر من مكان واحد.
  • اختصارات لوحة المفاتيح: C مهمة جديدة، A تعيين، S حالة، / بحث، ? قائمة الاختصارات.
  • Quick Add بلغة طبيعية: تصميم اللوغو بكرا 5م @أحمد !عاجل تتحول لمهمة كاملة.
  • Real-time عبر WebSockets (Laravel Reverb): التعديلات تظهر فوراً للجميع، مع Presence ("أحمد يشاهد هذه المهمة").
  • Optimistic UI، Dark Mode، PWA للموبايل.

6. الذكاء الاصطناعي (AI)

  • تلخيص نقاش مهمة طويل في سطرين.
  • توليد مهام فرعية من وصف المهمة.
  • تقرير أسبوعي تلقائي للمدير: ما أُنجز، ما تأخر، من تحت ضغط.
  • بحث ذكي باللغة الطبيعية ("ما المهام المتأخرة عند فريق التصميم؟").
  • كل ذلك بالعربي، وهنا نقطة ضعف Monday وNotion.

7. المساعد الصوتي (AI Voice Assistant) ⭐

مساعد يفهم العربية باللهجات وينفّذ الأوامر على النظام.

حالات الاستخدام

أوامر سريعة:

  • "ضيف مهمة تصميم اللوغو لأحمد، بدي ياها بكرا الساعة 5، وخليها عاجلة"
  • "حوّل مهمة الفاتورة لـ مكتملة"
  • "شو عندي مهام اليوم؟" / "مين متأخر بمشروع الموقع؟"

ميزات تبيع وحدها:

  1. ملخص صباحي صوتي: "صباح الخير، عندك 4 مهام اليوم، 2 متأخرين، وسارة علّقت على مهمة التصميم".
  2. الاجتماع إلى مهام: تسجيل الاجتماع، والمساعد يستخرج المهام ويعيّن المسؤولين والمواعيد تلقائياً.
  3. فويس واتساب إلى مهمة: الموظف يرسل رسالة صوتية للبوت فتُنشأ المهمة. مناسب جداً لسوقنا.
  4. تعليقات صوتية على المهام تُفرَّغ تلقائياً إلى نص.

البنية التقنية

🎤 صوت ← STT (تحويل لنص) ← LLM مع Tools ← Laravel API ← ✅ تنفيذ
                                                         ↓
                                  🔊 TTS (رد صوتي) ← تأكيد
  • STT: أصعب نقطة هي اللهجات (الشامية، الخليجية). نجرب أكثر من مزود على تسجيلات حقيقية قبل الاختيار.
  • LLM مع Tool Use: الموديل لا يلمس قاعدة البيانات أبداً. يستدعي أدوات (create_task، update_status، search_tasks، assign_task...) تنادي الـ API الحالي بتوكن المستخدم نفسه، فتبقى الأدوار والصلاحيات محترمة تلقائياً.
    • موديل سريع (Claude Haiku 5.5) للأوامر اليومية، وموديل أقوى (Claude Sonnet 5.5) لتحليل الاجتماعات والتقارير.
  • التأكيد قبل التنفيذ: أي حذف أو تعديل جماعي يعرض بطاقة تأكيد ("سأنشئ مهمة X لأحمد، موافق؟").
  • فهم السياق: "بكرا" و"الأسبوع الجاي" تُحسب حسب توقيت المستخدم، و"أحمد" تُربط بالمستخدم الصحيح من أعضاء المشروع (مع سؤال توضيحي عند وجود أكثر من أحمد).

ترتيب التنفيذ

الصوت طبقة إدخال فقط، والذكاء الحقيقي في الـ Agent خلفه:

  1. Command Bar نصي بالـ AI (داخل Ctrl+K، كتابة بالعربي): نبني فيه الأدوات والصلاحيات والتأكيد بدون تعقيد الصوت.
  2. زر المايك (Push-to-talk) فوقه: يصبح سهلاً لأن كل ما تحته جاهز.
  3. لاحقاً: الملخص الصباحي، تحليل الاجتماعات، بوت واتساب.

المخاطر

  • التكلفة: كل أمر = STT + LLM + TTS. يكون في الخطط المدفوعة مع حد شهري.
  • السرعة: أكثر من 2-3 ثوانٍ يقتل التجربة. نستخدم streaming وموديلاً سريعاً.
  • الخصوصية: تسجيلات الاجتماعات حساسة؛ سياسة واضحة للتخزين والحذف، مع خيار عدم الحفظ.

8. التعاون مع الخارج

  • Guest / Client Portal: العميل يرى تقدم مشروعه فقط، بدون العمل الداخلي.
  • Forms: فورم عام يتحول لمهمة (طلبات دعم، طلبات تصميم)، مع ربط الحقول بـ Custom Fields.
  • Email-to-task: عنوان إيميل لكل مشروع، أي رسالة تُحوَّل تصبح مهمة.

9. التكاملات (غير Bitrix)

  • WhatsApp: إشعارات + بوت لإنشاء المهام (نص وفويس).
  • Google Calendar / Outlook (مزامنة المواعيد).
  • Slack / Microsoft Teams (إشعارات وأوامر).
  • Public API + Webhooks: الشركات الكبيرة تطلبها قبل الشراء. توثيق كامل (OpenAPI) ومفاتيح API لكل Workspace.

10. البنية التجارية (SaaS)

  • خطط اشتراك + دفع (Stripe، أو بوابة محلية حسب السوق).
  • حدود حسب الخطة: عدد المستخدمين، التخزين، عدد الأتمتات، دقائق المساعد الصوتي.
  • Onboarding: معالج أول دخول، بيانات تجريبية، جولة تعريفية.
  • 2FA، وتسجيل دخول Google / Microsoft للشركات التي لا تستخدم Bitrix.
  • Audit Log موسّع على مستوى الـ Workspace.
  • Export / Import كامل (CSV، ومن Trello وAsana).

التميّز عن المنافسين

لن نغلب Monday بعدد الميزات، بل بالتخصص:

  1. Arabic-first: RTL متقن، واجهة عربية طبيعية، تقويم هجري اختياري.
  2. WhatsApp + Bitrix native: الأدوات التي تستخدمها شركات المنطقة فعلاً.
  3. AI ومساعد صوتي بالعربي واللهجات.
  4. تسعير محلي بعملة المنطقة.

أسئلة مفتوحة

  • هل يدخل Multi-tenancy قبل تكامل Bitrix أم بعده؟ (يؤثر على مكان تخزين إعدادات البوابة والتوكنات)
  • تصور المساعد الصوتي الأول: داخل الموقع، على واتساب، أم تسجيل اجتماعات؟
  • السوق المستهدف أولاً (دولة/منطقة)، لتحديد بوابة الدفع واللهجة الأولى للـ STT.
